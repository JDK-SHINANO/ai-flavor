# ai-flavor

中文「AI 味」的判定体系。把「读着像机器写的」拆成能数的指标、能查的词条、能复跑的对账。

词库 233 条，九个文体档，五个改写强度，三病三轴出诊断。

## 来历

这套东西起于 [blader/humanizer](https://github.com/blader/humanizer)（英文 34 条）和 [op7418/Humanizer-zh](https://github.com/op7418/Humanizer-zh)（中文 31 条）。两份清单都管用，我用了大半年。

用久了碰到三件事，清单应付不了。

一件是删不干净。清单式改法只做减法：可疑的词划掉，多余的连接词删掉。词能删到零，句子却越改越匀。上游 [issue #229](https://github.com/blader/humanizer/issues/229) 的盲测摆在那里：AI 词汇 70→0，排印 60→0，同期「均匀节拍」60→101、「格言式收尾」38→61。删完的文本没有瑕疵，也没有人味。

另一件是同一个词在两处，一处是病，一处是常态。「名词化」在学术论文里是日常，在散文里是硬伤；「总之」在公文里收束，在随笔里扫兴。不分文体的清单只能取最保守的判法，处处误伤。

还有一件更实际：改完怎么算好，没有指标，只能凭感觉。

分档、对账器、三病三轴，就是对着这三件来的。

## 三病三轴

| 病 | 是什么 | 轴 | 判据 |
|---|---|---|---|
| 甲 形合硬搬 | 英语的语法义务搬到汉语的可选位 | 纠偏 | 偏离汉语默认值，且没换来精度 |
| 乙 语域塌缩 | 全文只有一个语域，不对目标文体的路子 | 定域 | 偏离目标档的默认值，可高可低 |
| 丙 结构可预测 | 读者能猜出下一句的形状 | 破均 | 句长方差小、分节等长、金句位置可猜 |

三病正交，各有各的轴。混着治，必漏。

甲有一条前置：欧化有没有对价。有源文可依（翻译），欧化可能是忠实的代价，容忍度提一档；自己动笔而欧化，那是路径惯性，按病处理。

乙是双向的。散文写成公文是病，公文写成段子也是病，不是一律往口语化改。

丙的证据最强，处方最弱。人类与 AI 的分布差异有硬数（句长标准差差 1.37 倍），但「改高方差会让人更像人」没有干预实验。用时标为待验证。

## 分档

九个文体档：R1 学术、R2 公文、R3 技术文档、R4 新闻、R5 科普、R6 自媒体、R7 文学散文、R8 私人书信、R9 译文润色。每档有自己的默认值和硬约束，同一批词条落到不同档，严重程度不一样。

五个改写强度：L0 只诊断不动字，L1 删词法病灶，L2 再修句法，L3 动篇章结构，L4 重写。越往后越要人看着。

给谁看、改坏了什么后果，也进判据。进档案的（论文、公文、合同）降一档力道，只动确定项；一次性的消息可以放手改。

## 实测

同一把尺，量三类文本：

| 文本 | 字数 | 高置信命中 | 说明 |
|---|---|---|---|
| AI 合成的议论文 | 1076 | 7 | 典型模板腔 |
| 真人学术（一章） | 6744 | 0 | 二百余条词条，无一误伤 |
| 公文腔样例 | — | 3 → 1 | 降档后「抓手」「闭环」归为线索 |

新旧判据的对照实测另有两组，1270 字与 1076 字，档案在 `research/contrast-trials-2026-10/`。首轮结论：单跑 XH 优于单跑 ZH，优于两轮叠加；两轮会连带删掉限定语和主张。样本量还没到预设的 10–20 段，这一条只算初判。

## 怎么用

```bash
cd skill

# 画像与扫描
python3 scripts/af.py metrics 文件.md
python3 scripts/af.py scan 文件.md
python3 scripts/af.py scan --level 修辞 --min-conf high 文件.md
python3 scripts/af.py scan --register R2 公文.md     # 该档合法的词条降为线索

# 改稿对账：句长标准差、段长极差变小就报警
python3 scripts/af.py check 原稿.md 改稿.md

# 词库合并与校验
python3 scripts/af.py lexicon
python3 scripts/af.py lexicon --check
```

脚本只举证，不定案。它给行号、片段和置信度，判不判由人。

作为 Hermes skill 安装：

```bash
cp -r skill ~/.hermes/skills/creative/ai-flavor
```

## 依赖

Python 3.10 以上，无第三方硬依赖。装了 `jieba` 分词更准，口径与基线一致；不装会降级成最长匹配，词数分母按 1.704 字/词估算，输出多一列 `warn`。

```bash
sudo apt install python3-jieba
```

脚本会剔除表格行、代码块和 frontmatter。不剔的话整行表格会被当成一句话，实测能把最大句长从 48 字抬到 503 字，指标全废。

## 边界

判据有半衰期。基线上的模型和语料是 2024–2026 年的，连词密度、语气词密度这些倍率会随模型迭代移动，英文侧的 em dash 已经开始失效。过一两年要重测，不能当常数用。

采样语料以问答文本为主，倍率往文学、技术文档上外推要打折扣。人类基线是「可比语料」的分布，不是所有人类写作的分布；千字以下的短文本，只宜和同类短文本横比。
