# ai-flavor：AI 味的分档诊断与去除

一套**按文体分档**的判定体系。与 `humanize` 的区别：那个查「偏离汉语默认值」，本 skill 查**三件正交的病**，并且承认同一句话在不同文体里可以是病、也可以是常态。

## 何时用

- 判断一段中文像不像 AI 写的（不是「谁写的」，是「哪里不对劲」）
- 去除 AI 味、西式中文、机翻腔、模板腔、套话腔
- 在动笔前定「这批稿子该按什么标准改」
- 同一批文本要交给不同读者（导师、领导、公众号、朋友），需要分档处理
- 旧 `humanize` 判据在公文或散文上误伤时，来这里复核

不用于判定作者身份，不用于绕过 AI 检测器（这条路已被证伪，见 `references/50-evidence.md`）。

## 三病三轴

先认病，再开方。三病正交，各有各的轴，混着治必漏。

| 病 | 是什么 | 轴 | 判据一句话 |
|---|---|---|---|
| **甲 形合硬搬** | 英语的语法义务，搬到汉语的可选位 | 纠偏 | 偏离汉语默认值，且没换来精度 |
| **乙 语域塌缩** | 全文只有一个语域档，不对目标文体的路子 | 定域 | 偏离**目标档**的默认值（可高可低） |
| **丙 结构可预测** | 读者能猜出下一句的形状 | 破均 | 句长方差小、分节等长、金句位置可猜 |

**甲的关键前置**：欧化是否有对价。有源文（翻译）→ 欧化可能是忠实的代价，容忍度提一档；无源文（原创）→ 欧化是路径惯性，按病处理。

**乙是双向的**。散文写成公文是病，公文写成段子也是病。不要只往「口语化」一个方向改。

**丙的证据最强，处方最弱**。人类与 AI 的分布差异有硬数据（句长标准差 1.37×），但「改高方差会让人更像人」没有干预实验。用时标为待验证，不要当定理。

三病的证据、倍率与出处见 `references/10-model.md`。

## 流程：五步

### 第一步　过白名单闸

**先于一切。** 误伤的代价高于漏判——把「被评为」「数据的采集」「关于」当病灶删掉，改出来的中文反而不像中文。

贺阳（2008）后记的结论是硬边界：**汉语系统中不存在真正的恶性欧化，恶性只在个人言语**。所以白名单不是妥协，是语言事实。

白名单 11 项（他/她/它、关于、复合量词、限定集合的「之一」、术语位的性/化/度、中性「被」、人们、当……时、学术公文的「N 的 V」、系词「是」、常规标点）见 `references/20-whitelist.md`。命中白名单，直接放行，不进报告。

### 第二步　定档

两问定文体，一问定后果：

- **这是什么文体？** R1 学术 / R2 公文 / R3 技术文档 / R4 新闻 / R5 科普 / R6 自媒体 / R7 文学散文 / R8 私人书信消息 / R9 译文润色
- **给谁看？** 同行 / 上级 / 公众 / 朋友
- **改坏了什么后果？** 进档案（论文、公文、合同）/ 一次性（消息）/ 公开传播（公众号）

后果决定容错边界：不可逆的场合，改动力度**降一档**，只动确定项。

九档的默认值、硬约束与「特征 × 文体」矩阵见 `references/30-registers.md`。

### 第三步　扫三轴

先跑脚本拿数，再人工判。脚本只举证，不定案。

```bash
S=scripts
python3 $S/af.py metrics 文件.md                  # 画像：密度、句长分布、语气词
python3 $S/af.py scan 文件.md                     # 三轴×三层扫描，给行号与片段
python3 $S/af.py scan --register R1 --min-conf high 文件.md   # 按文体与置信度收窄
python3 $S/af.py scan --baseline b1.md b2.md -- 文件.md        # 与同文体对照样本比 z 值
```

**按等级与属性分派**：`--axis`（甲/乙/丙）、`--level`（词法/句法/篇章/语用/修辞）、`--min-conf`（high/mid/low）、`--register`（R1–R9）。不同属性走不同规则集——只查修辞层时不跑句法规则，标 R1 时把「公文正常」的词条降为线索。

扫的时候按病分组，不要全文盲扫（命中太少，噪声反而大）：

| 轴 | 扫什么 | 阈值 |
|---|---|---|
| 甲 | 每千词连词数、每句显性主语率、「们」用于非人、数词漏量词、条件从句后置率 | 连词 >25/千词起疑（人类基线 13，AI 36） |
| 乙 | 语气词数、口语词数、名词前「的」链长、NP 平均长度 | 语气词为零即警报（人类 16/千词，AI 3） |
| 丙 | 句长标准差、段落长度极差、并列短语数、元话语次数、可当名言收尾的句子数 | 句长标准差 <7（词口径）起疑 |

**没有通用基线，只有对照基线。** 句长与连接词不设绝对值，取同文体的原创样本比「均值 ± 标准差」。找不到样本时，用 `references/30-registers.md` 里的区间，并注明是估计。

### 第四步　推荐档位

读三样东西：情境三问的答案、文本画像、三轴扫描结果。然后给**四段式**：

```
推荐：L2 + R1（论文定稿），轴一优先
理由：连词 31/千词（基线 13）、每句显式主语、名词化 9 处其中 6 处可还原
      文本进档案、单一作者，故不动体式，只改可还原项与连接词
备选：L0 只诊断（若你还没决定要不要改）
不建议：L3 重写（会伤术语与限定；本文的限定句有实质约束力）
```

四段缺一不可。**「不建议」这一段最有价值**——它告诉使用者哪一档会毁掉这段文字。

调档规则：

- 后果不可逆 → 降一档
- 有源文（译文）→ 甲轴降权，乙丙照常
- 读者是外行 → 乙、丙升权
- 多人协作或品牌统一 → 不加个人声音，只做甲 + 丙的格式部分
- 文本已够 → 明说「不必动」，不要为展示工作量硬改

### 第五步　改，然后验收

处方见 `references/40-prescriptions.md`，验收表见 `references/60-failure-modes.md` §10。

**改写顺序**：甲 → 乙 → 丙。先纠偏，再定域，最后破均。反过来做（先打散节奏再改骨架），骨架会留在句子里，读起来仍不像中文。

**每改完一句必须回读**：拆掉名词壳或删掉连接词以后，主语还站不站得住、谓语还搭不搭。站不住就是拆塌了（「补的办法不是把闲聊搬到线上」→「要补，不是把闲聊搬到线上」，宾语悬空），换一种拆法，不硬拆。

## 档位：强度 L0–L4

| 档 | 名称 | 做什么 | 不做什么 | 典型场合 |
|---|---|---|---|---|
| **L0** | 诊断 | 只出报告：命中清单（带轴与编号）、三轴评分、档位建议 | 一字不改 | 作者自审、投稿前体检、给别人提意见 |
| **L1** | 轻扫 | 只删确定项：黑名单词、拔高、预告、免责、套话收尾 | 不重构句式，不动名词化 | 已成稿、只想去掉扎眼处 |
| **L2** | 标准 | 甲轴全面；乙轴局部；名词化只改「可还原且无精度损失」者 | 不动体式、不动结构 | 默认档 |
| **L3** | 重写 | 三轴全开：句法重构、语域重定、节奏打散 | 不改观点、不补论据、不加经历 | 初稿、代写稿、AI 草稿 |
| **L4** | 重铸 | 按指定样本或目标声音重写，可改结构与叙述顺序 | 不把别人的经历搬进正文 | 他人委托、品牌口吻统一 |

|---|---|---|---|---|---|---|---|---|---|
| R1 | 学术论文 | GB/T 7713.2 第 5.1 条：遣词造句应符合汉语语法 | ○ | ○ | × | △ | △ | △ | × |

| R5 | 科普 | 无 | △ | ○ | △ | ○ | ○ | ○ | △ |

| R7 | 文学散文 | 无 | × | × | ○ | ○ | ○ | × | × |
| R8 | 私人消息 | 无规范（见 §R8） | × | × | ○ | ○ | △ | △ | × |

**这张表是本书骨架。** 同一段文字在 R2 被判「名词化过度」，在 R7 被判「不够凝练」——这就是旧体系不带文体开关时方向相反的误判。九档细则与 12×9 矩阵见 `references/30-registers.md`。

## 预设

十二个常用组合。每个预设 = 一个档位 + 一条侧重 + 一条禁止线。

### 按人找档

| 你是谁 | 常写什么 | 起步预设 |
|---|---|---|
| 学生（课程论文、作业） | 期末论文、读书报告 | `paper-final` |
| 研究生（投稿） | 期刊论文、开题报告 | `paper-check` |
| 职场新人 | 周报、汇报、方案 | `report` |
| 公务员／事业单位 | 通知、请示、总结 | `gov-clean` |
| 程序员 | README、API 文档、发布说明 | `tech-doc`、`readme` |
| 自媒体作者 | 公众号、知乎、小红书 | `wechat` |
| 科普作者 | 长文、专栏 | `pop-sci` |
| 文学爱好者 | 随笔、散文、日记 | `essay` |
| 翻译／编辑 | 译稿、他人来稿 | `translation`、`ghost` |
| 只是写消息 | 微信、邮件 | `message` |

同一个人的不同场合要用不同预设。写论文的学生给导师发微信，不该套 `paper-final`。

### 档案类（后果不可逆，宁少改）

| 预设 | 组合 | 一句话 | 禁止线 |
|---|---|---|---|
| `paper-check` | L0 + R1 | 投稿前体检，只出报告 | 不动字 |
| `paper-final` | L2 + R1，甲优先 | 保术语与限定，只改可还原的名词化 | 不动体式，不动数据 |
| `grant-trim` | L1 + R1/R2 | 项目书瘦身，只删拔高与套话 | 不动论证结构 |
| `gov-clean` | L1 + R2 | 公文清稿，只删意义拔高与冗余框架 | 不碰四字格、被动、名词化、序数体式 |
| `report` | L2 + R2 | 工作汇报，甲 + 乙轻调 | 不加口语词 |

### 传播类（读者是外行，破均升权）

| 预设 | 组合 | 一句话 | 禁止线 |
|---|---|---|---|
| `tech-doc` | L2 + R3 | 保命令、版本、UI 加粗，去客服腔 | 不把步骤改成流水句 |
| `readme` | L2 + R3 | 同上，另查「希望这对你有帮助」 | 不动代码块与路径 |
| `news` | L2 + R4 | 去拔高与形容词，保留中性 | 不加评论 |
| `pop-sci` | L3 + R5，乙丙优先 | 打散节奏，准口语与比喻 | 比喻须带新信息 |
| `wechat` | L3 + R6，乙丙优先 | 破均为主，但防表演式口语 | 口语词须扎堆，不许均匀分布 |

### 私人 / 特殊

| 预设 | 组合 | 一句话 | 禁止线 |
|---|---|---|---|
| `essay` | L3 + R7 | 只留作者声音，删一切金句 | 不当「文学化」改写 |
| `message` | L2 + R8 | 短、直接、有语气词 | 不加书面连接词 |
| `translation` | L2 + R9 | 欧化有对价：容忍提一档，C 类不豁免 | 不改源文信息与逻辑连接 |
| `ghost` | L4 + R* | 按目标样本重铸 | 须作者确认声音样本 |

## 三条铁律

1. **保信息、保确定程度。** 不添原文没有的事实、数字、名字、日期、引文。不把「可能」改成「确定」，不把「计划」改成「已完成」。术语全文唯一。
2. **守编辑范围。** 润色不含摘要、扩写、补论据、改观点。不可逆场合力度降一档。
3. **只改真实存在的问题。** 检查点是线索，不是词表。没有问题的段落原样留着。

## 反向操作：不要做的事

以下七条由实证支撑，违反即自伤：

| 不要 | 因为 |
|---|---|
| 只在提示词里写「写得像人」 | 实测 0/17 通过，等于无效 |
| 一口气塞 30 条约束进 prompt | 500 条约束下最强模型仅 68%，且系统性偏向靠前指令 |
| 为正宗而换同义词 | 术语变三个写法，读者更困惑 |
| 为变化而机械抖动句长 | 「就这样。」「不难。」功能为零，最容易被读成「装」 |
| 为具体而补细节 | 无来源即编造，属硬失败 |
| 把精确改模糊 | 读者不会再有机会知道原文更准 |
| 改完更干净就交稿 | 词法清零但节拍变匀，反而更像 AI（实测均匀节拍 60→101） |

九种失败模式的识别方法见 `references/60-failure-modes.md`。

## 边界

- 本体系基于 2024–2026 年的模型与语料。判据有半衰期：em dash 在英文侧已开始失效，中文侧的连词与语气词倍率也会随模型迭代变化。**凡引用倍率，注明采样时间与语料类型。**
- 采样语料以问答文本为主，外推到文学与技术文档须谨慎。
- 人类基线取自可比语料研究，不是「所有人类写作」的分布。短文本（<1000 字）只宜与同类短文本横比。
